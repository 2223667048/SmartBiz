# 第六课：企业账号、租户隔离、文档权限、可恢复的异步索引（Windows + Docker）

> 起点：已完成第五课，Langflow 真实模型与云端 Embeddings 已通过测试。
> 验收目标：两个独立企业、两个权限级别、独立文档与来源、持久索引任务，以及回归测试。
> **本模块为本地可运行的强化 MVP，不等于通过正式商用安全审计。**

## 0. 不得跳过的兼容性说明

第五课使用 `kb_documents` 和 `kb_chunks` 作为一个共享知识库，并通过 `ADMIN_API_KEY` / `KB_SERVICE_KEY` 控制访问。单纯向旧表添加 `tenant_id` 不足以防止旧 API 绕过租户检查。

因此第六课采用 **独立新表**：`organizations`、`organization_users`、`organization_tokens`、`organization_documents`、`organization_chunks`、`indexing_jobs` 等。设置 `SMARTBIZ_MULTI_TENANT=true` 后：

- 旧 `/api/kb/*`、`/api/admin/*`、`/api/sessions`、`/api/chat`、`/api/tickets` 等 **全部返回 HTTP 410**；旧 `/admin` 页面也被关闭。`/api/catalog/search` 因为只返回公共演示目录而保留。
- 新系统入口为 `/workspace`，新业务 API 统一位于 `/api/v2/*`。
- 旧数据保留在数据库中、不会自动划归新企业。将以前用的原始文件重新上传到对应企业，才能得到真正的文档级所有权及可重新生成的索引；第五课原始文件未保留，因此无法无损自动迁移为可重试任务。
- 旧 Langflow `SmartBizKnowledgeTool` 使用 `/api/kb/search`，在新模式下不再可用。**从 Agent 流程上移除旧知识库工具，避免误以为它会执行租户授权。** 第六课的 `/api/v2/ask` 会先使用用户身份做范围内检索，再调用已经接好的 Langflow 生成答案。
- 先完整备份 `.env`、SQLite 数据库、Langflow 数据卷，不要盲目执行 `docker compose down -v`。

## 1. 源码模块及调用关系

```text
浏览器 /workspace
  ↓ 使用内存中的 Bearer Token （刷新后需重登）
FastAPI app/tenant_api.py
  ↓ 认证 app/tenant_store.actor_for_token() → {id, organization_id, role}
  ├── 管理员：建用户 / 上传 / 删除 / 重试 / 重建
  ├── 企业成员：查看授权文档与任务 / 检索 / 问答
  └── 操作均用服务端解析的 organization_id + 文档 visibility 约束
      ↓
SQLite app/migrations/0006_tenants.sql + app/tenant_store.py
  ├── 企业 / 用户 / 会话 / 文档 / 文本块 / 任务
  └── Worker app/tenant_worker.py 独立容器
      queued → running → succeeded / failed / canceled
      lease + worker_id + heartbeat + CAS 提交结果
```

旧版 `admin_auth` 与演示会话令牌不用于 v2 认证。

### 角色和文档可见范围

| 操作 | 企业 admin | 同企业 member | 其他企业任何角色 |
|---|---|---|---|
| 查询本企业公开文档 | 允许 | 允许 | 不允许 |
| 查询本企业仅管理员文档 | 允许 | 不允许 | 不允许 |
| 查询可见文档的索引任务 | 允许 | 允许 | 不允许 |
| 上传、删除、索引重试或重新索引 | 允许 | 拒绝 403 | 不允许 |
| 创建用户、查看企业用户 | 允许 | 拒绝 403 | 不允许 |
| 根据文档生成答案 | 本企业授权资料 | 本企业授权资料 | 绝不可串租户 |

不要从 HTTP 请求体、URL 查询或模型生成文本中获取可信 `organization_id`。它只能来自通过会话令牌查得的数据库用户记录。

## 5. 浏览器全程操作

打开 `http://127.0.0.1:8000/workspace`。

1. 用 `admin.a@example.com` 登录，验证企业账号及 `admin` 角色。
2. 上传 `examples/kb_support_policy.md`，可见范围先设为 `企业成员可见`。
3. 返回 `202` 后，在索引任务区查看 `queued`、`running`、`succeeded` 或 `failed`。需要时刷新。
4. 使用当前企业知识问答功能，查看 `answer` 和 `sources`。
5. 在用户区创建 `staff.a@example.com` 成员（单独初始密码）。
6. 登出，以成员身份登录；应能检索企业公开文档，但不能看到管理员操作按钮。
7. 登出，以 A 企业管理员登录，再上传另一份文档并选 `仅企业管理员`；切换为成员，验证该文档、索引任务、检索结果全部不可见。
8. 登出，登录 B 企业管理员账号，上传自己的资料。B 不应看到 A 的任何私有知识片段。
9. A 删除自己的文档后，文件及文本块将不再出现在结果中；任务审计记录保留为终态。

### 重要：任务状态并非上传进度百分比

`queued` 表示已写入持久队列；`running` 表示独立 Worker 已领取；`succeeded` 表示文件解析、云端 Embeddings 与 SQLite 提交成功；`failed` 表示出错，需要管理员检查后人工重试。任务记录包括 `attempts`、`created_at`、`started_at`、`finished_at`、`error_message`。进度百分比及任务取消协作仍待扩展。

### 异步处理与故障恢复

服务处理时由 `app/tenant_store.py` 在事务中领取任务并建立 15 分钟租约；`app/tenant_worker.py` 每约 30 秒更新租约。处理后验证任务仍属于原 Worker 并且文档未被删除，才能原子写入全部文本块和向量。Worker 崩溃后，其他 Worker 可以在租约过期后重新领取任务，最多 3 次；耗尽后标记失败，需要管理员重试。该方案使用 SQLite 和共享 Docker 卷，适合单节点、小规模任务，不是分布式生产消息队列。

## 6. REST API 与返回码

| 方法 | 路径 | 权限 | 用途 |
|---|---|---|---|
| POST | `/api/v2/auth/login` | 公开 | 账号登录，返回短期不透明 Bearer Token |
| POST | `/api/v2/auth/logout` | 已登录 | 使 Token 失效 |
| GET | `/api/v2/auth/me` | 已登录 | 查看登录身份（含可信租户 ID） |
| GET/POST | `/api/v2/users` | 管理员 | 用户列表/新增用户 |
| POST | `/api/v2/documents` | 管理员 | 表单 `file` 和 `visibility`，返回 202 + job_id |
| GET | `/api/v2/documents` | 已登录 | 根据租户和可见范围显示文档 |
| GET | `/api/v2/documents/{id}` | 已登录 | 查询自己的可见文档 |
| DELETE | `/api/v2/documents/{id}` | 管理员 | 删除并取消尚未完成的任务 |
| POST | `/api/v2/documents/{id}/retry` | 管理员 | 失败后重新入队 |
| POST | `/api/v2/documents/{id}/reindex` | 管理员 | 重新生成向量（保留原始上传文件） |
| GET | `/api/v2/jobs` | 已登录 | 授权任务列表 |
| GET | `/api/v2/jobs/{id}` | 已登录 | 查询授权任务状态 |
| GET | `/api/v2/search?q=...` | 已登录 | 按租户及文档 ACL 检索 |
| POST | `/api/v2/ask` | 已登录 | 先授权检索，再调用 Langflow 回答并返回引用 |

常见状态：`401` 无效或过期凭证、`403` 权限不足、`404` 文档或任务不存在（包括不属于你租户/角色不可见）、`409` 重复上传或旧 Embeddings 不兼容、`410` 旧版 API 停用、`422` 文件格式/大小/请求参数错误、`502` 云端模型异常。

例如通过 PowerShell 登录并查询任务（请勿打印 Token）：

```powershell
$secure=Read-Host "输入 admin.a@example.com 的密码" -AsSecureString
$password=[System.Net.NetworkCredential]::new("",$secure).Password
$payload=@{email="admin.a@example.com";password=$password} | ConvertTo-Json
$login=Invoke-RestMethod -Uri "http://127.0.0.1:8000/api/v2/auth/login" -Method Post -ContentType "application/json; charset=utf-8" -Body ([System.Text.Encoding]::UTF8.GetBytes($payload))
$headers=@{Authorization="Bearer $($login.access_token)"}
Invoke-RestMethod "http://127.0.0.1:8000/api/v2/jobs" -Headers $headers | Format-Table state,attempts,created_at
Remove-Variable password,payload -ErrorAction SilentlyContinue
```

## 7. 数据库隔离关键 SQL

```sql
SELECT d.id, d.filename, d.status
FROM organization_documents d
WHERE d.organization_id = :trusted_organization_id
  AND d.status != 'deleted'
  AND (d.visibility = 'organization' OR :trusted_role = 'admin');
```

`:trusted_organization_id` 与 `:trusted_role` 来自服务器通过 Bearer Token 查询到的数据库用户记录，**绝不由用户、Agent 或 HTTP 客户端直接指定**。元数据、向量检索和任务结果都采用相同的租户与 ACL 过滤。在 SQLite 上，这是应用层隔离，**没有 PostgreSQL Row Level Security**；跨表联接和新模块都必须重复安全检查和测试。

**当前未实现**：一人加入多企业、细粒度分享、SSO/MFA、邮件激活、邀请链接、组织审计日志、独立密钥/加密盘、文档病毒扫描、数据保留与删除证明、分布式锁/消息队列、Worker 资源限额/配额、网关级限速与正式 SLA。原始文件保留在 `smartbiz-data` 数据卷用于重试/重建，**不要上传真实敏感资料**，直到完成加密存储和权限安全审计。

## 8. 源码推荐阅读顺序

1. `app/migrations/0006_tenants.sql`：实体、外键、唯一索引、租户字段。
2. `app/tenant_store.py`：Argon2id、哈希 Token、登录限制、租户限制、入队及查询。
3. `app/tenant_api.py`：FastAPI `Depends(require_actor)` 和 `require_manager`；绝不使用用户输入的租户 ID。
4. `app/tenant_worker.py`：领取任务、文档提取、Embedding、事务提交、失败处理。
5. `web/workspace.html/css/js`：表单、访问令牌的内存存储、来源渲染、任务状态。
6. `tests/test_lesson06.py`：两个租户、角色可见性、失败重试、租约回收与旧接口封堵。

## 10. 排错与回滚

| 问题 | 排查 |
|---|---|
| `/workspace` 显示 503 | `.env` 添加 `SMARTBIZ_MULTI_TENANT=true` 并重建 SmartBiz |
| 登录 401 | 先执行 `tenant_admin create-org`；注意邮箱和密码是否匹配 |
| 登录 429 | 同一来源和账号 5 分钟内失败太多，稍后再试 |
| 上传始终 queued | `docker compose ps` 检查 worker 容器、Docker 共享卷和日志 |
| 任务 failed | `/api/v2/jobs/{id}` 查看安全错误类型，结合 Worker 日志修复，然后管理员 retry |
| HTTP 409 旧模型 | 上传后已用旧向量，调整 Embeddings 配置时每文档手动 reindex，直到兼容 |
| 旧 Langflow 知识库工具异常 | 第六课关闭了不具租户意识的 `/api/kb/search`，请不要恢复共享后门 |
| Cloud Embeddings 502 | Docker Worker 的 `.env` API Key、Base URL、联网状态和模型权限 |
| 数据库 locked | 检查是否存在其他长事务或磁盘性能问题；本项目仅适用于低并发测试 |

**回退至第五课（维护窗口操作）**：先停止 SmartBiz 和 worker，备份当前数据库，然后将 `SMARTBIZ_MULTI_TENANT=false`、恢复第五课 `docker-compose.yml`、`app/main.py` 等旧代码，使用第五课镜像重建。新表仍留在数据库内，不会自动删除；旧知识库仍在原表中。不要直接拿不含第六课代码的容器重新执行第六课 API。
