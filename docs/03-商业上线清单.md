# 商业上线前的必做项

当前代码仅是工程验证 平台版本。不要仅因能在本地跑通就面向公网售卖。

## 安全与身份
- 企业级 OAuth/OIDC 或完整用户鉴权，员工/管理员 RBAC；当前 ADMIN_API_KEY 仅适用于受控本地管理。
- 由服务器反向代理配置 HTTPS / HSTS / CSP / 严格 CORS；禁止直接将 Langflow 管理端暴露公网。
- 边界级 IP + 用户 + 租户限流、验证码/滥用检测、LLM Token 配额与成本预警。
- 对 Langflow Agent 工具配置最小权限，禁用任意代码执行或命令工具的非必要访问。
- 知识库按客户/租户隔离，包括 embedding、检索过滤、文档 ACL 与日志。
- 测试 prompt injection、敏感信息泄漏、恶意文件、SSRF、越权、幻觉。

## 数据与合规
- 向客户明确说明用途、保存期限、处理者、删除/导出方式；实现删除 API 与定期清理任务。
- 对联系信息加密、限制查询、保留访问审计日志，履行适用的隐私/数据跨境要求。
- 与模型服务商确认商用条件、数据留存、地区合规；估算模型 API 成本。

## 工程质量
- 正式环境将本项目 SQLite 换 PostgreSQL 并做迁移版本管理，数据库备份和定期恢复演练。
- Langflow 及 Python 依赖固定具体版本与镜像 digest；升级前测试。
- 引入工作流导出、CI、集成测试、监控、日志脱敏、超时预算、重试/熔断、队列。
- 评估并发：SQLite 本地模式和内存式机制不保证多副本一致性。
- 对外品牌、域名、用户协议和隐私政策，以及上游许可证的版权保留。

## 商业验收例子
10 位测试客户各提 20 个 FAQ：收集正确率、无依据回答比例、人工转接率与一次成功率；模拟 100 并发请求测试超时与失败率。验收阈值应由业务风险和 SLA 共同确定，不要拍脑袋写“准确率 100%”。
