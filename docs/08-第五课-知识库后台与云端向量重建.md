# 第五课：RAG 知识库可视化管理后台与云端向量重建

适用：**Windows 10/11 + Docker Desktop**，已完成第四课并已有真实 Langflow 模型工作流的 SmartBiz 项目。本课为**本地教学 MVP**，不能当成已满足企业安全要求的 SaaS。

## 0. 本课验收标准

1. `http://127.0.0.1:8000/admin` 可以用 `.env` 中的 `ADMIN_API_KEY` 登录。
2. 登录后可查看文档数量、文本块数量、索引版本/兼容性。
3. 可以上传合法 PDF/DOCX/TXT/MD，看到**网络传输进度**；上传结束后单独提示“后台提取/向量化中”，最终能刷新文档列表。
4. 可以删除演示文档；未经登录及缺少 CSRF 的删除/上传请求被拒绝。
5. 可以不生成答案地检索 Top-K 文本块，也可以通过现有 Langflow Agent 回答并列出来源文件、页码、片段、相似度。
6. 能测试新的云端 Embeddings（不会修改索引），备份数据库后重建旧索引，显示 `compatible: true`；云端失败不会清空旧数据。
7. 原有第四课功能与本课新增功能的自动化测试全部通过。

## 1. 工程与选型

沿用**原生 HTML/CSS/JS** 而不引入 React/Vue：现有项目就是无前端编译的原生页面，此举可以立即兼容第四课的 FastAPI `StaticFiles`，无需新增 Node 构建链。第五课目的是理解 API 边界和浏览器安全；后期可以把这套接口迁移到 Vue 3 / React。

新增／修改文件：

| 文件 | 责任 |
|---|---|
| `app/admin_auth.py` | 管理员浏览器会话：随机令牌、SQLite SHA256 哈希、8 小时失效、CSRF、退出登录 |
| `app/kb.py` | 获取索引版本与文本块快照、事务性重建全部向量 |

| `web/admin.html` | 管理后台完整页面 |
| `web/admin.css` | 双列桌面布局、移动端布局、上传/来源信息样式 |
| `web/admin.js` | Cookie 会话、API、上传进度、文档增删、索引操作与证据展示 |
| `web/index.html` | 加入“知识库后台”入口 |

## 3. 管理后台实际 API

| 请求 | 功能 | 安全边界 |
|---|---|---|
| `POST /api/admin/ui/login` | 交换密钥为管理员 Cookie | 错误凭证拒绝；简单登录限速 |
| `GET /api/admin/ui/me` | 恢复已登录管理会话 | HttpOnly Cookie |
| `POST /api/admin/ui/logout` | 注销管理会话 | Cookie + CSRF |
| `GET /api/kb/documents` | 文档列表 | X-Admin-Key 或有效管理 Cookie |
| `POST /api/kb/documents` | 上传文档并索引 | 同上，Cookie 方式还需 CSRF |
| `DELETE /api/kb/documents/{id}` | 删除文档和块 | 同上，Cookie 方式还需 CSRF |
| `GET /api/admin/kb/index` | 查看新旧 Embedding 版本是否兼容 | 管理员 |
| `POST /api/admin/kb/embedding-test` | 发出一次测试向量请求、不写索引 | 管理员；云端模式可能计费 |
| `POST /api/admin/kb/reindex` | 向量批量重建与原子替换 | 管理员；`{"confirm":"REINDEX"}` |
| `GET /api/admin/ui/kb/search` | 可视化检索 | 管理员浏览器 Cookie |
| `POST /api/admin/ui/kb/ask` | 受保护的后台 RAG 问答 | 管理员浏览器 Cookie + CSRF |

第四课旧接口 `GET /api/kb/search` 和 `POST /api/kb/ask` 保留，继续由后端内部 `KB_SERVICE_KEY` 保护。**管理前端绝不接收此密钥**。

### 为什么不是直接在 JS 写 ADMIN_API_KEY？

浏览器 JS 可查看，存 `localStorage` 容易因 XSS 泄露。因此管理员只在登录时发送强密钥给同源后端，后端生成不可预测随机 Cookie 令牌，在 SQLite **只存令牌哈希**。Cookie 标记 HttpOnly、SameSite=Strict；具有写操作的后台请求必须额外包含 CSRF 令牌。这个机制是单管理员 MVP 的边界，不是正式的密码账户、MFA、RBAC 或多租户实现。

本地 HTTP (`127.0.0.1`) 时 `.env` 维持 `ADMIN_COOKIE_SECURE=false`。正式 HTTPS 环境才设 `true`，同时必须做反向代理、HTTPS、会话管理、审计日志、RBAC、多租户及第三方安全评估。

## 4. 云端 Embeddings：先探测，再重建

### 4.1 修改 `.env`，不要修改 Langflow 的聊天模型

```powershell
notepad .env
```

只改知识库向量相关变量：

```dotenv
RAG_EMBEDDING_MODE=openai
RAG_EMBEDDING_BASE_URL=https://api.openai.com/v1
RAG_EMBEDDING_MODEL=text-embedding-3-small
RAG_EMBEDDING_API_KEY=你的云端EmbeddingAPIKey
RAG_EMBEDDING_DIMENSIONS=
RAG_MIN_SIMILARITY=0.25
```

注意：
- `RAG_EMBEDDING_API_KEY` 不一定是第三课 Langflow 聊天工作流使用的同一服务凭证。
- 默认 `text-embedding-3-small` 的维度为 **1536**；`text-embedding-3-large` 默认 **3072**。`RAG_EMBEDDING_DIMENSIONS=` 留空表示使用模型默认维度。
- 若使用支持 `dimensions` 参数的模型，可以尝试设为 `512` 等有效值，后端会向 `/embeddings` 请求传入 `dimensions`，并把维度写入索引版本指纹。**改变 dimensions 也要重建索引**。
- 如果是第三方“OpenAI 兼容”服务，请使用**该服务实际提供**的 Base URL / 模型名 / 密钥，不能假设任何模型都支持 `dimensions`。
- 当前索引规格使用 Base URL + 模型名 + 可选 dimensions；提供商在 URL 和名称不变时静默更新模型仍可能需要人工重建。

保存后**只重建 SmartBiz 容器，让 `.env` 的新环境变量生效**：

```powershell
docker compose up -d --force-recreate --no-deps smartbiz
```

### 4.2 先查看状态（不会产生云端向量费用）

后台 `/admin` 登录后，查看“索引状态”。若之前用 demo 建索引，应该显示 **需要重建**。此时旧版 `/api/kb/search` 或 RAG 问答可能返回 **409**：这是避免混合不兼容向量的正确保护。

可选择执行自动化的只读探测脚本：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\lesson05-cloud-check.ps1
```

脚本只做登录、获取索引状态、发送**一次短文本 Embeddings 请求**、注销，不修改旧索引。输入管理员密钥时不回显。

也可在 `/admin` 点击 **测试 Embeddings 连接**。成功示例：`云端模型；维度 1536；索引未修改`。该接口仅证明网络、凭证、返回向量结构通畅，不表示 RAG 质量已经达标。

### 4.3 数据库备份已确认后再重建

在“向量索引管理”区域点击“重新生成全部向量”，按提示输入 `REINDEX`。后端：

1. 读取 SQLite 中所有已保存 `kb_chunks.content`。
2. 按批次调用当前配置的 Embeddings 远程接口，得到归一化向量。
3. 在事务中再次核对文本块快照，确认没有同时被修改或删除。
4. 更新所有 `kb_chunks.vector / dimension`，最后更新 `kb_documents.embedding_spec`。
5. 事务提交以后，新旧规格一致，管理后台显示“可用”。

若第 2 步服务不可达：**不会修改原索引**，重建返回 HTTP 502；若第 3 步有并发修改，返回 HTTP 409。可以恢复旧的 `.env` 模式继续使用原索引，然后排查云端网络 / 密钥 / 限流问题。已经成功重建后想切回原模型，**需要再次重建**或从备份恢复，不要只改 `.env`。

由于本课依旧是小型教学服务，重建是在一次 HTTP 请求中执行、可能持续较久；现在**不是**队列化后台任务，关闭浏览器、代理超时或容器重启的用户体验并不适合大规模商业使用。生产方案应升级为任务队列 + 状态机 + 双索引构建 + 原子索引指针切换。

### 4.4 验证真正的语义检索

后台“知识问答实验室”：

- 先点击“**只测试检索**”，确认模型检索出合理的文件名和原文片段；这一步只调用 Embeddings，没有生成式聊天模型调用。
- 再点击“**检索并生成回答**”，确认自然语言答案末尾含 `[1]` 等引用编号，右侧来源列表能对应。
- 用**不在知识库中的问题**做反例，记录是否误召回或编造；根据实测评估 `RAG_MIN_SIMILARITY`、chunk_size / overlap、top-k。不要因为出现引用编号就声称准确率 100%。

## 5. 逐文件源码精读

### 5.1 `app/admin_auth.py`：谁能操作后台？

```python
session = admin_auth.session_for_cookie(request.cookies.get(admin_auth.COOKIE_NAME))
if not session:
    raise HTTPException(status_code=401, detail="请登录管理后台")
```

登录时原始密钥不会保存在前端存储，服务端只记录会话 token 的 SHA-256 哈希；注销时删除对应记录。浏览器通过 HttpOnly Cookie 自动携带会话，不能从 JS 中读取 token。CSRF 防护不等于内容权限：该课程暂时只有一个共享管理员身份，不可用于隔离不同企业的数据。

### 5.2 `app/main.py`：API 控制器不要写业务算法

- `require_kb_manager()`：保持原有 PowerShell `X-Admin-Key` 兼容，也支持后台 HttpOnly Cookie；Cookie 写请求必须通过 CSRF。
- `/api/admin/kb/index`：获取当前模型规格、旧索引规格、chunk 数量，零向量调用成本。
- `/api/admin/kb/embedding-test`：只计算一次短文本向量，返回维度，不写 SQLite。
- `/api/admin/kb/reindex`：编排快照读取、向量生成和事务提交。
- `compose_rag_answer()`：把上一课的检索→提示词→Langflow→来源返回整理成共用逻辑，避免用户端 API / 管理后台重复实现。

### 5.3 `app/kb.py`：索引数据结构与一致性

```python
current = [dict(r) for r in conn.execute(
    "SELECT id, content FROM kb_chunks ORDER BY document_id,position"
).fetchall()]
if current != snapshot:
    raise KbConflictError("重建时文档发生变化；未修改原索引，请重试")
```

这里不是重新上传 PDF，而是读取已存在的每个文本块并重新向量化。`BEGIN IMMEDIATE` 开始写事务，验证快照未变再 `UPDATE`。事务完成前，不发布新 `embedding_spec`。`documents.id` 保持不变，所以旧来源引用仍可关联到相同文档（但实际检索排序可能变化）。

### 5.4 `app/embeddings.py`：为什么要记录模型与维度？

```python
payload = {"model": model, "input": batch}
if dims is not None:
    payload["dimensions"] = dims
```

默认将文本批量发给 `/embeddings`，取得 `data[i].embedding` 后做归一化。向量维度不是检索正确性的唯一条件：**即使同样是 1536 维，不同模型的向量也不能直接混用**。因此必须用 `embedding_spec` 识别模型来源，而非只检查 `dimension`。

### 5.5 `web/admin.js`：如何显示上传“进度”？

```javascript
xhr.upload.onprogress = event => {
  if (!event.lengthComputable) return;
  const percent = Math.round(event.loaded / event.total * 100);
  // 这里只表示浏览器已传出的文件字节百分比，不能代表后台向量化进度。
};
```

使用 XHR 而非普通 `fetch`，因为它能报告**浏览器向后端传输的字节进度**。传输完成后，界面提示“正在提取文本并生成向量”，**不虚构嵌入处理进度**。完整上传与索引完成后才视为成功。正式生产版应使用入库任务 ID + 轮询/SSE/WebSocket 报告提取、分块、Embedding、索引各阶段真实进度。

### 5.6 `web/admin.js`：引用展示与 XSS 防护

```javascript
const excerpt = document.createElement('p');
excerpt.textContent = item.excerpt;
```

无论上传的文本还是大模型输出，都用 `textContent` 展示，不把不可信字符串写入 `innerHTML`。来源项展示 `citation`、`filename`、`page`、`position`、`similarity`、`excerpt`，其中“相似度”是向量相关性，不是概率，更不是事实正确率。

## 6. 验收与错误排查

在你自己的 Windows Docker 环境中执行：

```powershell
docker compose run --rm --no-deps -v "${PWD}:/srv/app" -w /srv/app -e AGENT_MODE=mock smartbiz python -m pytest -q
```

然后用 Swagger 或管理后台测试以下失败场景：

1. 未登录访问 `GET /api/kb/documents`：403。
2. 正确登录后上传合法文档：201。
3. 已登录但不带 CSRF 直接 POST/DELETE：403。
4. 上传相同字节的文件：409。
5. 云端模式仍保留 demo 索引：检索 409，索引状态 `requires_reindex=true`。
6. 云端连接测试失败：502，**旧索引未被删**。
7. 重建成功后：`requires_reindex=false`，文档 ID 不变，检索/问答仍可用。

错误日志：

```powershell
docker compose logs --tail 80 smartbiz
```

- `403`：权限、错误密钥或缺少 CSRF，先判断请求来自 PowerShell 还是浏览器。
- `409`：重复文档/旧向量不兼容/重建期间数据改变。
- `422`：输入无效、上传文件不能解码、JSON 格式不符合 API。
- `502`：当前远程 Embeddings 或 Langflow 服务调用失败；检查 API 地址、模型、密钥、额度、网络、容器日志。
- `503`：环境未配置管理员密钥，或 RAG 答案当前处于 mock 模式。

## 7. 商用前必须补齐的能力

**目前不足以对客户销售为安全的多企业知识库**，主要因为：

- 当前单管理密码，而非 OAuth/OIDC、MFA、RBAC；无企业和用户角色。
- 共享知识库，缺少租户 ID、文档级 ACL、越权隔离测试。
- SQLite 全表向量扫描，不适合大量文档；应迁移到 PostgreSQL + pgvector / 向量数据库。
- 无任务队列、进度持久化、失败重试、幂等、用量预算和云模型调用成本报表。
- 上传解析器尚需恶意文档沙箱、内容检测、文件类型检查及合规数据处理策略。
- 无结构化审计事件、数据删除和保留政策、备份恢复演练。
- 管理页面仅本机 HTTP，Cookie Secure 为 false；生产必须 HTTPS、反向代理与安全加固。
- 原始 PDF 不持久化，无法跨切分规则重新抽取，只能为既有块重算向量。

**后续第六课建议**：账号体系和企业级租户隔离（SQL `tenant_id`、行级权限、文档 ACL）、后台入库任务队列及原子索引版本切换。此优先级比美化页面更高。
