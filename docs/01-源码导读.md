# 原仓库源码阅读地图

官方仓库 https://github.com/langflow-ai/langflow

以 2026 年 10 月可见的 Langflow 1.12 架构为背景：

- `src/frontend/src/`：React + TypeScript 前端，画布/UI；初期只浏览，不修改。
- `src/backend/base/langflow/api/`：FastAPI 路由（重点读 `v1/endpoints.py` 的运行入口）。
- `src/backend/base/langflow/services/`：鉴权、数据库、配置、监控等服务。
- `src/backend/base/langflow/graph/`：图执行相关封装。
- `src/backend/base/langflow/components/`：内置组件（部分逻辑已经拆成 lfx）。
- `src/lfx/`：共享轻量执行引擎与组件定义。
- `src/bundles/`：模型与工具提供商集成。

注意：目录随版本变化；优先以所检出版本的 AGENTS.md、DEVELOPMENT.md 与源码为准。

## 阅读顺序
1. 工作流 UI 中用鼠标连出 Chat Input → Model → Chat Output。
2. 打开 Langflow 的 API access 面板查看 `/api/v1/run/{FLOW_ID}`，打印 JSON 原始响应。
3. 读 `src/backend/base/langflow/api/v1/endpoints.py`，搜索 `/run/` 或 `run_flow` 等函数定义，理解参数校验与路由。
4. 读 `src/backend/base/langflow/graph/` 与 `src/lfx/`，重点理解节点如何获取输入、执行并产出 Message。
5. 读 `app/langflow.py`，了解“防腐层”：业务项目不用依赖 Langflow 的全部内部类。
6. 读 `app/main.py` → `app/db.py`，了解请求与数据落库。

## 我们的服务的调用路径
浏览器 `web/app.js` → `POST /api/chat` (`app/main.py`) → `ask_agent()` (`app/langflow.py`) → Langflow `/api/v1/run/{flow_id}` → 解析 `outputs[..].results.message.text` → SQLite (`app/db.py`) → 浏览器安全显示。

## 四个必须自己讲清楚的问题
- 为什么 API Key 只能放后端？
- 为什么 session_id 不能直接等同于用户身份认证？
- 为什么 mock 返回“演示模式”而不能声称真正调用了 AI？
- 为什么模型回答即使语气自信，也可能不来自企业文档？
