# 第九课｜修复浏览器上传 HTTP 500 + 商用部署可观测性

## 0. 安全与范围

前置条件：第八课 PostgreSQL 版已运行，Windows PowerShell、Docker Desktop、两个**隔离测试企业**已创建。禁止用真实客户/生产数据库运行自动化破坏性测试。上线前须做独立安全评审、备份还原演练、承载能力评估。此课只提供本地与受控环境可运行的基础设施，不代表已完成生产认证。

问题现象：Playwright 第一次上传时看到 `HTTP 500`。现有数据库有 `idx_pg_active_digest`：同租户的**未删除**文档以内容 SHA256 去重；旧 Playwright 测试只随机化文件名，却始终用相同 bytes，重复运行容易触发 `psycopg.errors.UniqueViolation`。旧 API 只捕获 SQLite 的 `IntegrityError`，不会捕获 PostgreSQL 异常。因此这是首要**假设**，但最终必须以 SmartBiz 容器 traceback 为准。若 traceback 显示 `PermissionError`、`InsufficientPrivilege` 等，请参见故障定位表，不能直接当重复文件。

### 0.1 确认原始原因（修补前）

```powershell
cd C:\AI\smartbiz-agent-starter
$dc = @('--env-file','.env','--env-file','.env.pg','-f','docker-compose.yml','-f','docker-compose.pg.yml')
docker compose @dc logs --since 10m smartbiz
```

观察关键字符串 `idx_pg_active_digest` / `psycopg.errors.UniqueViolation`；注意测试运行之前的日志是否已轮转。旧 API 对重名不同内容不去重，对不同名相同内容去重。若 500 原因不是这个，先停在此步，提供堆栈的异常类型和错误 SQLSTATE（请打码敏感信息）。

### 0.2 变更说明与测试

- `app/tenant_api.py`：只捕捉 SQLSTATE `23505` 且约束为 `idx_pg_active_digest` 的 PG 冲突为 409；其他数据库错误仍抛出，不掩盖错误。
- `browser-e2e/test_tenant_browser.py`：每次生成独特文件内容；增加**同一文档重复提交应 409**，并继续验证 A/B 页面隔离。
- `tests/test_lesson09.py` / `tests/test_lesson09_pg_live.py`：后端冲突映射单元测试和真实 PostgreSQL 上传两次的测试。

预期 `0009_pg_budget (head)`。迁移新建 `tenant_model_estimates`、`worker_heartbeats`，并执行 `ALTER ROLE smartbiz_worker NOBYPASSRLS`。上一课初始化脚本曾设置 `BYPASSRLS`，**新迁移会修复已有数据库角色**，只修改初始化脚本对已有卷无效。第八课 Worker 专用 RLS 策略需要已正确安装。


## 4. Caddy HTTPS 与安全响应头

第九课可选 `docker-compose.ops.yml` 启动 Caddy、Prometheus、Alertmanager、聚合指标服务。**这不是一键公网生产部署**。默认 `.env.ops` 中 `SMARTBIZ_DOMAIN=localhost`，Caddy 对 localhost 使用本地 CA，浏览器可能报证书不受信任；此为预期现象，不要在生产中采用 `curl -k` 或忽略证书。

要使用公网域名，请满足：DNS A/AAAA 指向服务器公网 IP；80/443 TCP 可达（QUIC 需 UDP/443）；云防火墙允许；域名控制权真实。修改 `.env.ops` 的 `SMARTBIZ_DOMAIN=your-real-domain.example`。Caddy 根据域名自动申请和更新证书；浏览器使用 `https://<域名>/workspace`。

启动：

```powershell
docker compose @dc up -d caddy ops-exporter prometheus alertmanager alert-sink
```

确认配置语法：

```powershell
docker compose @dc exec caddy caddy validate --config /etc/caddy/Caddyfile
docker compose @dc logs --tail 70 caddy prometheus ops-exporter alertmanager
```

本地测试可访问 `https://localhost/workspace`（本地 CA 需自行信任）。确认 `/internal/metrics` 经 Caddy 请求返回 404，只有带 Bearer Token 的内部 Prometheus 才可访问该路由。Caddy 添加 CSP、HSTS、X-Content-Type-Options、Referrer-Policy、X-Frame-Options、Permissions-Policy；限制 POST 文件请求体 3MB。**应用仍在 Docker 基础 Compose 上绑定 127.0.0.1:8000** 作为本机调试通道；正式部署需修改为不可通过外网绕开 Caddy，并隔离管理面（Langflow 等）。

官方文档： https://caddyserver.com/docs/quick-starts/https ；https://caddyserver.com/docs/caddyfile/directives/request_body

## 5. Prometheus 与审计、结构化日志

`app/observability.py` 将每条 HTTP 请求生成 `request_id`，记录路由模板、状态码、耗时 JSON 行，**不记录请求体、API Key、邮箱、文档内容、原始路径 ID**。`X-Request-ID` 可关联请求与容器日志。日志暂时为单容器 stdout，没有自动集中存储和保留策略。`/internal/metrics` 需要一个独立、足够长的 Bearer Token；Caddy 完全拒绝外部访问它。

Prometheus 管理界面只映射到 Windows 本机 `http://127.0.0.1:9090`，Alertmanager 为 `http://127.0.0.1:9093`；不要把这两个面板开放到公网。`ops-exporter` 的端口不对主机发布。Prometheus 通过 Docker 服务域名抓取：
- `smartbiz:8000/internal/metrics`（鉴权 token 从 `ops/secrets/metrics_token` 读取）
- `ops-exporter:9105/metrics`（仅内网，聚合队列与 Worker 心跳）

指标包括 `smartbiz_http_requests_total`、`smartbiz_http_request_duration_seconds`、`smartbiz_index_jobs`、`smartbiz_queue_oldest_age_seconds`、`smartbiz_worker_last_seen_age_seconds`、`smartbiz_model_budget_max_reserved_ratio`。禁止加入租户 ID、电子邮箱、Token、用户问题作为 metric label。

Alertmanager 将告警发送至示例 `alert-sink` 日志接收器：

```powershell
docker compose @dc logs --tail 30 alert-sink
```

告警会被规则计算与本地记录，但**不会给你发真实短信/邮件**。正式环境需配置可用的邮件/IM/值班系统接收器，以及故障演练与降噪策略。

## 6. 模型预算：预估额度，而非实际账单

`app/cost_budget.py` 与 `tenant_store_pg.reserve_model_estimate()` 在发出 Langflow 生成请求前，为租户按 UTC 日预留固定 `SMARTBIZ_RESERVE_PER_CALL_USD`（默认 0.02 美元），每日额度 `SMARTBIZ_DAILY_ESTIMATE_USD`（默认 2.00 美元），使用数据库原子 UPSERT。超出时返回 429。失败调用保留预估占用，不自动释放以避免逃逸；数据库表不包含真实 Token 使用量。

**非常重要**：Langflow 内部可能再次调用模型；不同模型每次成本不同，Embedding 在预留之前已发生；这个预算不能保证真实云端支出不超额，也不是账单。要做真正硬性封顶，还需限制模型最大生成 token、从模型网关获取 usage、按供应商价格表计算实付成本并与供应商配额或账单对账。千万不要把 `reserved_micro_usd` 当作真实美元费用向客户计费。

## 8. 回滚方案

1. 停止外部入口与写入：`docker compose @dc stop caddy smartbiz worker ops-exporter`。
2. 恢复上一课代码（事先备份整个项目或 Git commit），旧版 Web/Worker 无需使用新表。不要删除数据卷，也不要无计划删除第九课产生的审计和预算记录。
3. PostgreSQL 保留 `0009_pg_budget` 新表是最保守的代码级回滚；如果需要回退迁移，在**隔离数据库副本**中先测试 `alembic downgrade 0008_pg_ops`，确认没有需要保留的数据后才可在维护窗口执行。
4. 迁移中已撤销 Worker `BYPASSRLS`；**不要为了回滚而恢复 BYPASSRLS**。如果旧版 Worker 因依赖旁路权限而失败，应暂停 Worker，修复 RLS，而不是重新授予超权。
5. 从 `pg_dump` 还原必须在独立数据库演练，并核对表、文档和向量行数。第九课运行期间新增的数据不会自动回写第八课快照，旧备份直接覆盖会丢数据。
