## A. 真正的大模型：Langflow 内部配置

1. 打开 `http://127.0.0.1:7860` 并登录，点击 `New Flow` → `Simple Agent` 模板；不同小版本可以创建 Blank Flow，连接 `Chat Input → Agent → Chat Output`。
2. 打开 Settings → Model Providers，选择你**自己合法获得 API 密钥**的模型服务商。填写模型提供商的 API Key，启用你获授权使用、**支持 tool/function calling** 的聊天模型。若使用本地 Ollama，按其官方配置把 Langflow 指向**容器可访问**的 Ollama 地址；容器内的 `localhost` 不是 Windows 宿主机。
3. Agent 中选择已启用的模型，并设置清晰的 Agent Instructions：

```
你是 SmartBiz 企业助手。回答仅限经过工具核实的业务数据。
对于报价、价格、交付时间，若工具没有给出正式数值，不得编造。
仅当问题需要服务目录时使用 SmartBiz 服务目录查询工具。
工具结果标明 demo_only=true 时，明确告知这是演示数据。
不得捏造工具执行结果、订单、客户或工单记录。
```

4. 打开 Playground，测试 `你好，请用一句话介绍你自己。`。观察是否真实调用了模型。
5. 在 Langflow 用户设置创建 **Langflow API Key**（与模型提供商 API Key **不同**）。从工作流 Share → API access 获取 **flow ID**。接口使用 `/api/v1/run/{flow_id}`，当前工程适配器已经实现。

在项目的 `.env` 中设置（不要将真实值发给任何人）：

```dotenv
AGENT_MODE=langflow
LANGFLOW_FLOW_ID=<复制的Flow ID>
LANGFLOW_API_KEY=<Langflow平台API Key>
```

`LANGFLOW_URL` 在 Compose 里被设为 `http://langflow:7860`，因此 `.env` 中的本机地址无需修改。

```powershell
docker compose up -d --force-recreate --no-deps smartbiz
```

验证配置是否加载，**只输出布尔值，不打印密钥**：

```powershell
docker compose exec smartbiz python -c "import os; print('AGENT_MODE:', os.getenv('AGENT_MODE')); print('has_flow_id:', bool(os.getenv('LANGFLOW_FLOW_ID'))); print('has_langflow_key:', bool(os.getenv('LANGFLOW_API_KEY')))"
```

打开 SmartBiz `http://127.0.0.1:8000`，进行真实模型聊天。若报 `502`，先检查 Langflow Playground 能否独立运行，再核查 flow ID、Key、工作流输出是否为 Chat Output：

```powershell
docker compose logs --tail 80 smartbiz
docker compose logs --tail 80 langflow
```

## B. 验证 Agent 会话记忆

**SmartBiz 的历史记录（SQLite）≠ Agent 的记忆（Langflow）**。本项目 `app/langflow.py` 发起请求时包含 `session_id`：

```python
body = {
    "input_value": text,
    "input_type": "chat",
    "output_type": "chat",
    "session_id": session_id,
    "output_component": "",
}
```

Langflow 1.12.x 的 Agent 默认提供内置记忆，使用 Langflow 的存储。先用这个功能，不要同时加外部 Message History 重复注入消息。

**测试一：相同会话**

- 在 SmartBiz 发送「我的测试代号是蓝鲸7412，后续请记住。」
- 再发「我的测试代号是什么？只回答代号。」
- 预期：大概率回答 `蓝鲸7412`。如果失败，检查两个请求的会话 ID 是否一致、Agent 是否真的启用了记忆及 Chat Input/Output 是否正确连线。

**测试二：隔离新会话**

- 点击网页上的新建会话。
- 发送「我之前设置的代号是什么？」
- 预期：不能读取旧会话的 `蓝鲸7412`；理想回复是「当前会话中没有提供」。模型的语言行为并非强安全证明，还要验证业务 API 的令牌隔离。

**测试三：刷新后复用当前会话**

- 同一浏览器标签页刷新并继续提问。
- 前端 `sessionStorage` 会保留当前标签页的 session token，后端找到相同 `session_id`；新的 Langflow 调用应继续复用该上下文。

每个环节要区分：`session_token` 是服务器签发的用户会话**凭证**；`session_id` 是内部会话**标识符**，不能单独用于授权读取客户数据。

## C. 把 SmartBiz 业务接口变成 Langflow Agent 工具

### C1. 业务 API 先独立工作

```powershell
Invoke-RestMethod 'http://127.0.0.1:8000/api/catalog/search?q=知识库' | ConvertTo-Json -Depth 6
Invoke-RestMethod 'http://127.0.0.1:8000/api/catalog/search?q=报价' | ConvertTo-Json -Depth 6
```

说明：这个 API **仅返回公开演示目录**，不返回客户、订单或工单，工具只能查询，不能修改业务数据。

### C2. 在 Langflow 导入自定义工具代码

1. 打开当前 Simple Agent 工作流，点击 Core components 或 Bundles → `New Custom Component`。
2. 选择组件的 `Code` 编辑器。
3. 用 VS Code 打开本地 `extensions/smartbiz_catalog_tool.py`，**全选复制**，替换组件编辑器代码，点击 `Check & Save` 或相应的 Save。
4. 在该组件上启用 **Tool Mode**；当输入字段已经有 `tool_mode=True` 时，菜单位置/显示可能有所变化。连接组件 `Toolset` → `Agent` 的 `Tools` 端口。
5. 如果界面提示 `lfx` import 不可用，请先确定 Langflow 运行版本；1.12.x 使用 `lfx` 路径。如使用旧版本，请升级或改为兼容的 `langflow.custom`, `langflow.io`, `langflow.schema` 导入路径。
6. 保存工作流（**仍使用同一个 FLOW_ID** 时无需重新修改 .env）。

工具代码重要片段：

```python
inputs = [MessageTextInput(name="query", display_name="查询关键词", tool_mode=True)]
outputs = [Output(name="result", display_name="服务目录结果", method="search_services")]
# 服务端固定地址，不允许模型拼接动态网络地址
endpoint = "http://smartbiz:8000/api/catalog/search?" + urlencode({"q": query})
```

`http://smartbiz:8000` 是 Docker Compose 网络中的服务名，不是 Windows 浏览器地址。浏览器用 `http://127.0.0.1:8000`，容器互通用 `http://smartbiz:8000`。

### C3. 测试真正的工具调用

在 Langflow Playground 发出：

> 请**调用 SmartBiz 服务目录查询工具**检索「工单」，告诉我返回的服务名称。请说明这是演示数据，不要编造报价。

**重点验收：** 不仅要看到答复中出现「工单」，还要打开 Playground 的运行轨迹/工具调用记录，确认 Agent 确实调用了 `search_services`（或工具面板中显示的对应动作），并检查返回结构有 `source=smartbiz-demo-catalog`、`demo_only=true`、`count=1`。如果只是模型回答而没有工具执行，说明**工具未真正打通**。

再到 SmartBiz 网页问相同问题，确认也通过 `SmartBiz → FastAPI → Langflow → 工具 → FastAPI` 调用了相同的工作流。

### 常见问题

- **Langflow 能回答但 SmartBiz 502**：核对流程 ID、Langflow API Key、输出节点类型；后端解析器需要聊天文本输出。
- **模型说不记得**：确认当前工作流为 Agent（内置记忆），两轮请求使用同一 `session_id`，没有点击新建会话。
- **工具 HTTP 访问失败**：工具跑在 Langflow 容器内，必须用 `http://smartbiz:8000`，而不是 `localhost:8000`。用 `docker compose ps` 看两个容器是否运行。
- **工具已连接但不调用**：检查 Tool Mode、Tools 连线、工具动作是否启用、模型是否支持函数/工具调用，先用明确命令「请调用……工具」。
- **返回演示数据但模型报出具体金额**：模型幻觉或指令不足。检查 Agent Instructions 和工具输出，**金额必须由业务后端真实数据提供**。
- **模型服务超时或余额不足**：排查模型提供商 Key、额度、代理与容器网络；平台无法代替你购买或验证密钥。
