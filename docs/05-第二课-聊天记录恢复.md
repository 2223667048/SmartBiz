# 第二课：为 SmartBiz 增加「刷新后恢复聊天记录」

本章基于第一课的工程，设计、实现并测试一个小型端到端功能。

## 需求 / 验收

- 用户在当前浏览器标签页完成聊天并刷新，显示最近 50 条消息（最多允许 API 查询 100 条）。
- 仅通过 `X-Session-Token` 返回本会话消息；其他会话不可读取。
- 没有令牌返回 HTTP 401；非法 `limit` 返回 422。
- 页面用 `textContent` 呈现消息，禁止把模型生成内容当 HTML 执行。
- 页面刷新后可继续给原 AI 消息留下反馈。
- 本功能只是历史展示；它**不会**使 Langflow 自动拥有长期记忆。

## 涉及文件

1. `app/db.py`：新增 `list_session_messages(session_id, limit=50)`，参数化 SQL，按时间顺序返回最近消息。
2. `app/main.py`：新增 `GET /api/messages`，依赖已有 `require_session` 做身份边界，`Query` 限制上限。
3. `web/app.js`：初始化会话后恢复历史，回复用 `bubble` 安全渲染。
4. `tests/test_api.py`：增加跨会话隔离、顺序、上限、权限的自动化测试。

## 浏览器验收

- 访问 `http://127.0.0.1:8000`，发一条测试问题；只刷新当前标签页（F5），之前的问题与回答仍然可见。

- 打开浏览器的另一个独立会话环境（例如隐私窗口）不应看到原会话历史。

## 代码解读：数据库侧

```python
def list_session_messages(session_id: str, limit: int = 50) -> list[dict]:
    with connection() as conn:
        rows = conn.execute(
            """
            SELECT id, role, content, created_at
            FROM (
                SELECT rowid AS sort_order, id, role, content, created_at
                FROM messages
                WHERE session_id = ?
                ORDER BY rowid DESC
                LIMIT ?
            )
            ORDER BY sort_order ASC
            """,
            (session_id, limit),
        ).fetchall()
    return [dict(row) for row in rows]
```

`WHERE session_id=?` 是租户/会话隔离在数据访问层上的基本防线；`LIMIT ?` 控制最多取回多少行。使用嵌套查询是为了拿到**最近的 N 条**消息之后，再按发送顺序呈现。不要用字符串格式化把 session_id 或 limit 拼进 SQL。

## 代码解读：HTTP 层

```python
@app.get("/api/messages")
def my_messages(
    session_id: str = Depends(require_session),
    limit: int = Query(default=50, ge=1, le=100),
):
    return db.list_session_messages(session_id, limit)
```

`Depends(require_session)` 自动校验 `X-Session-Token` 并解析会话身份；`Query` 验证 URL 参数（1~100）。浏览器不能直接传 `session_id` 来读取别人的历史。

## 代码解读：页面恢复

`web/app.js` 会在页面初始化时调用 `GET /api/messages?limit=50`，用 `bubble()`（内部 `textContent`）显示消息。只在得到历史数据时替换初始欢迎语。API 回复里的 `id` 用于重建评价按钮。

`sessionStorage` 保存在浏览器标签页的页面会话中，关闭标签页后不保证可恢复；将来做登录制客服系统时，要改成账号身份和服务端会话列表，而不是无限期保管演示令牌。
