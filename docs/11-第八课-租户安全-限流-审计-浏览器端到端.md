## 4. 为什么新迁移补 Worker RLS？

第七课 RLS 对 `smartbiz_app` 角色设置了租户数据策略，防止普通 Web API 跨企业读取。**独立 `smartbiz_worker` 是一个信任等级更高的后台进程**：它必须从多个企业共同的任务队列中选择任务。数据库表 `GRANT` 权限不等于 RLS 允许；没有 Worker 专用策略，读取队列、完成索引可能被拒绝。

新迁移对 Worker 显式设置 SELECT/UPDATE/INSERT/DELETE（仅需要的表与操作），而仍不授予 `SUPERUSER` 或 `BYPASSRLS`。这表示 Worker 具有跨企业操作范围：它的 DSN 仅应存在于 Worker 容器，绝不能放进 SmartBiz Web 前端或浏览器。

## 5. 接口及源码分析

### 5.1 限流

`tenant_api._throttle(actor,'ask'/'search'/'upload')`：从**已验证的 actor** 取 `organization_id`，调用后端 `store.consume_rate_limit()`。超过配置上限时返回 `HTTP 429` 和 `Retry-After`（秒数）。

PostgreSQL 使用单条原子 `INSERT ... ON CONFLICT DO UPDATE SET hits=hits+1 RETURNING hits`，所有 Web 副本连接同一数据库，防止进程内计数失真。按 60 秒固定窗口，允许跨边界的短暂突发，不保证精确平滑流量；需进一步配合反向代理、模型超时、每日预算、队列限制与 API Key 安全。

`GET /api/v2/search`、`POST /api/v2/ask`、`POST /api/v2/documents` 受限制。注意上传请求在进入 Python 依赖前可能已由 Web 框架接收，因此必须在反向代理中另配置请求体尺寸上限以防上传滥用。

### 5.2 账号停用与令牌撤销

`POST /api/v2/users/{user_id}/disable`：必须为本企业管理员；只能停用同企业用户；不能停用自己或企业最后一位启用的管理员；把 `active` 置为 `false`，并在**同一个事务**中删除所有登录 Token。下一次 API 调用中 `actor_for_token()` 会返回空，HTTP 401。浏览器收到 401 清空工作台。

需要区分：被撤销之前已发出的请求可能仍在处理；令牌撤销无法撤回浏览器已经显示的内容。正式生产需结合敏感页面自动锁屏、短时令牌、响应防缓存和审计。

### 5.3 索引任务监控

`GET /api/v2/jobs/metrics`：仅企业管理员可访问，返回 `counts`（按 state 统计）、`oldest_queued_seconds` 和 `stale_leases`。数据库查询以当前登录租户为准；PostgreSQL 还施加 RLS，企业 A 无法聚合企业 B 的数据。

`stale_leases > 0` 说明某些任务租约过期，可能需要检查 Worker；`oldest_queued_seconds` 较大说明队列积压。这些数据不等于实时 CPU、容器健康或 Worker heartbeat；生产还需要日志集中收集与告警。

### 5.4 操作审计

`GET /api/v2/audit` 仍用于查看单个租户的操作事件。本课新增管理员 `GET /api/v2/audit/summary`，按 action/outcome 汇总近 24 小时事件。停用账号写入 `user.disable`。敏感密码、令牌、完整向量、用户提示词不应存入审计详情。

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\lesson08-smoke.ps1
```

## 7. 限流和撤销的验收

在**测试** `.env` 中将 `SMARTBIZ_SEARCH_PER_MINUTE=2`，重建 SmartBiz 容器（仅测试系统），管理员登录，连续三次访问 `/api/v2/search?q=test`：前两次预期 200，第三次预期 429 并带 `Retry-After`，同一企业另一账号也应 429，企业 B 不受企业 A 的计数影响。切换到新的自然分钟窗口，重测应恢复。

使用企业 A 管理员工作台创建临时成员，记录其测试 Token，管理员点击「停用账号」。随后该 Token 请求 `/api/v2/auth/me` 应为 401；企业 B 管理员不能停用 A 的成员，应返回 404。停用自己返回 409；当前至少保留一位有效管理员。

**为了避免云端模型费用，不要在限流实验里大量调用 `/api/v2/ask`。** 优先使用无索引的独立测试企业，或者用自动化测试的 Mock 模型检查 429。

### 8.3 Windows Chromium 真实浏览器测试

该步骤在 Windows 主机 PowerShell 进行，**不要依赖 Docker 容器已经安装浏览器**。需有 Python 3.12 可用：


先在两个**专用测试企业**准备 A/B 管理员。不要使用客户数据的生产库。这些测试**会创建测试文档与测试账号**。

```powershell

```

可追加 `--headed` 查看浏览器逐步运行。运行完成后清理环境变量：

验收必须看到两个浏览器测试通过：A 上传的唯一标识文件不能出现在 B 的工作台；退出登录清空问答内容；被停用的账号 Token 被服务器拒绝。

## 9. 升级失败、回滚与安全边界

- **迁移失败**：保持 SmartBiz/Worker 停止。记录 `docker compose @dc run --rm migrate` 报错并检查是否存在部分手工改动。不要直接删除 PostgreSQL 数据卷。
- **代码有问题但 DB 迁移成功**：先停止写入，恢复 `lesson08-backup` 的上一课代码以及前端文件。旧代码一般不依赖新增限流表，可以先保持 0008 结构；若必须做架构级回滚，先在隔离副本验证 `alembic downgrade 0007_pg_tenant`，再进行（会删除限流记录和本次补充的 Worker RLS 策略）。
- **全量数据库恢复**：保存 PostgreSQL 快照后，在独立测试数据库验证 `pg_restore`，确认账号数、文档数、向量块数和审计记录。生产恢复应采用单独受控的变更计划，避免覆盖升级后的数据。
- **浏览器状态**：本次只实现登录切换与服务端撤销后的下一次请求检测，不提供强制远端清除所有旧标签页缓存的保证。
- **生产差距**：网关级限流、长周期预算、SSO/MFA、设备登录会话列表、可验证的审计留存、实时 Worker 心跳、告警、对象存储、密钥轮换、端到端加密和专业渗透测试仍不在本课范围。
